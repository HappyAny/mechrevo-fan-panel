# 硬件写入与恢复设计

接口依据为 [mech-forza-control 的固定版本](https://github.com/minortex/mech-forza-control/tree/3a8df18b91a86b3a21951b8cd1d1418f86dec6ca) 中的 fan.py、registers.py、backends/windows.py，以及 [w568w 的 WUJIE14XA 研究](https://gist.github.com/w568w/b2fc5f9d1f4dff13efe751abec27b396)。本机实测结果另存 validation。

写入白名单：0xF20–0xF2F、0xF50–0xF5F 两组 16 点占空比表；0x727 bit6、0x741 bit0、0x751 bit6、0x7C5 bit7、0x7C6 bit2；渐变速度 0x787。
百分比乘 2 写入表。更新时关闭表管理门，写完两张表后再启用。共享位采用读、掩码修改、写、回读检查。
本机原有非激活表的阈值异常，因此只使用全部 16 档相同占空比的固定表，不依赖阈值切换。退出后恢复原字节。
0x783–0x786 仅读；非零则拒绝启用共享 Custom 路径，不通过清零功率值来强行启用风扇。

后台每轮检查温度、RPM、PWM、控制门和表字节；外部修改或长期无法达到目标时退出手动。
界面每 500 ms 发送心跳。后台检查父进程 PID、启动时间和进程存活状态；心跳 4 秒超时、管道关闭或父进程退出时恢复并结束。
后台退出后，界面通过持久恢复记录处理未完成恢复。全局命名对象阻止本工具多实例同时控制。
记录只接受完整白名单地址，拒绝任意地址；同次开机才能恢复 RAM，重启后不重放旧字节。

恢复失败时保留记录，尝试 FanBoost 并明确报告。无法保证内核/驱动失效、两进程同时终止或硬件故障时完成恢复。
工具不改固件、BIOS、CPU 电压、功率寄存器或官方配置文件，不安装服务或开机任务。
