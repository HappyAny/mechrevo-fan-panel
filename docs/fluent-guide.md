# 无界风扇 2.0.1 · Fluent

为机械革命 WUJIE14XA / BIOS N.1.14MRO20 制作的原生 Windows 风扇工具。
界面采用 .NET 10 官方 WPF Fluent 主题，提供浅色、深色和跟随系统外观。
EXE、窗口标题栏和任务栏使用同一蓝色五叶风扇图标；源码内附 SVG、PNG、9 种尺寸的 ICO 和生成脚本。

## 使用

双击 `Mechrevo-Fan.exe`。单文件已内置 .NET 10.0.14，无需 Python；仍需本机已安装官方控制中心附带的 ACPIDriver。
先关闭旧版风扇窗口，两个版本共用单实例锁。

- **自动**：交还本次手动操作前的风扇控制状态。
- **手动风量**：双风扇联动，20–100%，每格 1%；进入手动后拖动即生效。
- **满速强冷**：打开硬件 FanBoost。
- 实时显示 CPU 温度、两个风扇的 RPM 和实际占空比。百分比是 PWM 占空比，不是最大 RPM 的线性比例。
- 风扇会用数秒渐变到目标，滑块位置不代表实际风量已经达到目标。
- 右上角菜单切换外观或查看开源许可。

## 温度保护

| CPU 温度上升到 | 最低风量 |
|---|---:|
| 65°C | 40% |
| 75°C | 65% |
| 80°C | 80% |
| 85°C | 100%，并启用 FanBoost |

降温时有迟滞，避免来回切换；强冷保护在降至 78°C 后解除。
界面分别显示用户目标和当前生效目标。保护不能关闭，不提供停转或低于 20% 的手动设置。

## 退出与故障恢复

手动操作前先保存恢复记录。普通退出、4 秒心跳超时、窗口进程异常退出由独立后台恢复；后台异常退出由窗口进程尝试恢复。后台仅在本次会话中运行。
恢复会逐字节还原原来的占空比表及本工具改变的控制位，保留外部改变的性能档位和不相关控制位。

记录通常在 `%LOCALAPPDATA%\MechrevoFanPanel\recovery-v2.json`；该目录不可写时使用 EXE 旁的 `state` 文件夹。
同一次开机中，下次启动会处理未完成记录；重新开机后不重放上次开机的 RAM 数据。
手动控制期间不要移动 EXE 或删除恢复记录。

系统崩溃、驱动卡死、两进程同时被终止或硬件故障不属于已保证范围。恢复失败时工具会尝试强冷并明确提示，请正常重启电脑。

## 实现边界

直接通过已安装的官方驱动读写已验证的 EC 地址，不需要 MQTT 密码或网络连接。
只写两组占空比表、风扇相关控制位和渐变速度；不写 CPU 功率、电压、BIOS、固件或官方配置文件。
非零功率/温度覆盖项会阻止启用共享 Custom 路径；其他程序占用自定义表时也拒绝接管。
检测到外部修改风扇表或性能档位后退出手动控制。不要同时使用其他第三方风扇工具。

## 验证与源码

- `validation/native-tests.json`：1% 步进、温度保护、部分写入失败回滚、外部状态保护、恢复记录验证。
- `validation/hardware-duty.json`：实机双风扇达到 45%、65%、80%、81%；温度保护会提高部分请求。结束后风扇备份字节和功率寄存器均匹配原值。
- `validation/hardware-lifecycle.json`：心跳超时、后台终止、主进程直接退出均确认恢复，孤立后台自行退出。
- 属于短时功能验证，不代表每个百分比、所有负载、睡眠/唤醒和长期温控均已验证。

源码位于 `desktop/FanPanel`。安装 .NET 10 SDK 后执行 `python build_fluent.py`；Python 仅用于构建打包，不是运行依赖。
`--self-test <输出文件>` 使用模拟硬件；`--probe <输出文件>` 只读硬件；`--hardware-test` 和 `--lifecycle-test` 会短时改变风扇后恢复。
